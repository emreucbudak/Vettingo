# Personalized job posting publication

Evaluation Application exposes `IPersonalizedJobPostingPublisher.PublishAsync` with
`PersonalizedJobPostingDto`. Call it with the posting generated by the future RAG
flow. The DTO contains `UserId`, `Title`, `PublishedDate`, `CityId`, and `Salary`
(`int`, nonnegative). No HTTP endpoint or evaluation CRUD trigger is added.

```csharp
await publisher.PublishAsync(new PersonalizedJobPostingDto
{
    UserId = userId,
    Title = title,
    PublishedDate = publishedDate,
    CityId = cityId,
    Salary = salary
}, cancellationToken);
```

CAP publishes the DTO to `vettingo.job.personalized-job-posting.requested.v1`, using
PostgreSQL message storage and RabbitMQ. Both API projects register CAP on startup
and read `ConnectionStrings:DefaultConnection` and the existing `RabbitMq`
configuration keys. Docker Compose supplies these settings for both APIs and waits
for RabbitMQ to be healthy before starting them.

Job Infrastructure consumes that topic in group `vettingo.job-service`, validates
the received fields, and sends `CreatePersonalizedJobPostingCommandRequest` through
FlashMediator to the existing handler. Salary is persisted and returned in both
personalized listing queries. CAP retries failed processing; delivery is at least
once, so a replay after a committed insert can produce another posting.

Job posting create/update requests and responses now expose one nonnullable `int`
`Salary`. Search keeps optional integer `MinSalary`/`MaxSalary` bounds and applies
them to that single salary value.

For an existing Job database, run
`src/JobService/Vettingo.JobService.Persistence/DbContext/Scripts/20261008_SingleSalary.sql`
before starting the updated API. It uses the old minimum salary when present,
otherwise the maximum, otherwise 0, and rounds to an integer. It then removes the
old range columns and adds Salary to personalized postings with a default of 0 for
existing rows. The transaction rolls back if a legacy value exceeds `int` range.
Fresh databases obtain the new schema through the existing `EnsureCreated` flow.
